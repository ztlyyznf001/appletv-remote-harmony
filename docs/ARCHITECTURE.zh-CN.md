# 架构与安全边界

## 分层

1. **ArkUI / ArkTS**：设备选择、PIN 输入、遥控按钮、可见错误、前后台状态。
2. **Network Kit mDNS**：发现 `_companion-link._tcp`，逐个 resolve 服务得到 IP 和真实端口。服务名、TXT、IP 均是不可信定位信息。
3. **Universal Keystore Kit / HUKS**：设备内 AES-GCM 封装密钥；Preferences 仅持有版本、随机 IV、密文与认证标签，配对凭据不明文落盘。无法解密时要求重新配对，不退回明文。
4. **Node-API 边界**：少量明确类型的 Promise API，把阻塞 TCP 与密码计算放在工作线程；没有把 C++ 对象地址暴露到 ArkTS。
5. **C++ Companion**：TCP、消息编解码、配对、身份验证、会话、基础按键。只有成功验证已保存 Apple TV 身份并打开会话后，界面才显示已连接。
6. **OpenSSL 3**：EVP 密码原语与成熟 BIGNUM。不是使用自写哈希/曲线/AEAD，也不链接 Android `.so` 或 JVM JAR。

采用独立 C++ 核心是为了让 SRP 大整数与 64 位计数不依赖 ArkTS `number`，并先在可用主机工具链上跑可重现的密码向量与 loopback 测试。Android 模块暂时不共享这一新核心，避免首轮改动已发布 Android 版。

## 配对与身份

- 第一次配对必须由用户选中设备并输入电视显示的四位 PIN。
- SRP 是 HAP 使用的 RFC5054 3072-bit / SHA-512 变体，用户名 `Pair-Setup`，包含服务端 proof 校验。
- Pair Setup 后保存的是控制器 Ed25519 身份与已验证的 Apple TV 公钥/身份；不保存 PIN。
- 每次连接用新的 X25519 临时密钥做 Pair Verify，并核对电视身份和签名。相同服务名/IP 不能覆盖已保存身份。
- Pair Verify 后分别派生 `ClientEncrypt-main`、`ServerEncrypt-main`。收发方向各有独立 64 位计数；四字节帧头进入 AEAD AAD。
- 会话断开后清零可控的秘密缓冲；不承诺运行时、操作系统或 GC 从未留存任何临时副本。

## 请求、取消与按键

- TCP 是字节流，短读、分片和合并不改变协议消息边界。长度、递归深度与格式错误在继续处理前被拒绝。
- 命令按 XID 匹配，穿插事件不能提前当作命令成功；总期限不因无关事件而无限延长。
- 取消递增操作代数并关闭/唤醒 I/O；即使异步任务随后结束，过期结果也不能把 UI 恢复成已连接。
- 基础按键只提供原子点击，没有暴露“按住直到下次调用释放”的 UI。down/up 两帧组成同一输出缓冲，发送后才等待两个 XID 回复；因此不会在等待 down 回复的十秒内持续按住。出错或生命周期中断时尽力释放；如果断网发生在部分 TCP 写入途中，仍无法保证电视收到最后的 up。
- 后台不运行常驻服务。重连次数受前台会话限制；用户主动断开后不偷偷连回。不存在无限重试或重放旧按键。

## 不可信输入与错误

mDNS 名称、网络字节、OPACK/TLV 字段、凭据文件都必须验证。原生错误使用稳定短码和固定安全信息；不把电视返回的任意字符串或秘密拼接到日志。PIN 不写日志、文件、分析事件或崩溃注释。

手动入口只用于当前局域网的数字 IP 和实际端口。发现广播并不证明它是 Apple TV；用户选中后才请求配对。多播失败时不做全网端口扫描。

Preferences 不提供条件事务。若后台取消恰好发生于密文异步落盘期间，会尽力回滚旧值；进程死亡或磁盘故障可能保留候选密文，不能宣称“取消与落盘”具备崩溃原子性。回滚失败后当前进程禁止继续使用存储。HUKS 密钥丢失且仍有密文时，不自动生成替代密钥；恢复可能需要用户确认后在系统设置清除应用数据，届时所有本机配对都会丢失。

## 未完成的保证

- 尚未用 Harmony SDK 编译检查 ArkTS、HUKS、mDNS、Node-API 声明或目标链接。
- 尚未测 API26 手机、HUKS 密钥删除/系统恢复、权限拒绝、Wi-Fi 切换、多播网络隔离。
- 尚未以真实 tvOS 验证省略 `_touchStart` 的按钮会话是否被所有目标版本接受。
- 合成 loopback 与密码向量不能证明 Apple TV 兼容性，也不能替代安全审计。
- 没有宣称 FIPS 认证、Apple 授权或 AppGallery 审核保证。
